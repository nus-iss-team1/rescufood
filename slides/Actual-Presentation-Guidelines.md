# Practice Project Presentation

**for Graduate Certificate — Designing Modern Software Systems (Stackable)**

> This is the **actual** presentation guideline (converted from `SWE5006 - Practice Project Presentation Guidelines.docx`). It supersedes the earlier predicted guideline.

## General Presentation Outline with approximate suggested time allocation (40 minutes)

> **Note:** The time for Q&A is included in the overall duration. The timings for the following segments are given in the form `(X+Y)` where Y is the Q&A time.

### 1. Overview (2+1 minutes)
- Explain the context and the business problem that the solution as a whole is trying to achieve.
- Explain the scope of the project.

### 2. Project Conduct (2+1 minutes)
- Explain the current status of the project including outstanding issues.
- Describe the actual project milestones and the total effort expended by each team member.
- Explain how many sprints were planned, and the Definition of Done (DoD) achieved.
- Sprint retrospective & reflection in the next sprint.

### 3. Software Architecture & Design (7+2 minutes)
- Software architectural decisions that influence the logical architecture.
- Transition from analysis to design.
- Use case diagram.
- Analysis and design models.
- Design problems and patterns.
- Database schemas.

### 4. DevSecOps and Development Lifecycle (6+2 minutes)
- Describe the strategy to manage the source code and artifacts.
- Describe the DevSecOps pipeline and procedures.
- Highlight any technical findings and issues encountered.

### 5. Demo (13+4 minutes)
- Demonstrate some of the significant use cases of the solution.
- Demonstrate how the solution deals with some of the important quality attributes, e.g.:
  - **scalability** (such as demonstrating auto-scaling),
  - **performance** (show using some scripted performance testing),
  - **maintainability** (show/run the DevOps pipeline).

---

## Presentation Tips

1. Summarize and highlight the significant achievements. Talk more about the significant and interesting parts of the solution and implementation. Your audience should remember the unique aspects of the solution and not similarities to other solutions.
2. Manage your time well. Do not present too many slides. Remember that the audience can read the text in the slide, so refrain from reading them.
3. Explain your design in a top-down manner. Make sure that your audience understands the requirements, the high-level design and the high-level decisions that you make before drilling into some details.
4. Ensure that the contents on the slides are readable from the distance at which your audience is sitting. This is particularly true for face-to-face presentations.
